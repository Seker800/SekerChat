# 01-spec.md

## 1. Goal

把订阅中心从“全文表单信息流”调整为结构清晰的 Markdown 发布与阅读中心。

## 2. Product Definition

### 2.1 In-scope

- 删除内容类型、手工摘要和独立外部链接。
- 统一内容模型为标题、标签、Markdown 正文和附件。
- 列表卡片显示自动正文预览，点击后显示完整详情。
- Markdown 编辑、预览、常用格式工具栏和安全渲染。
- 上传图片并在光标位置插入正文。
- 标签胶囊输入，支持回车、空格、中英文逗号和批量粘贴。
- 列表筛选调整为全部、未读、有附件、已置顶。

### 2.2 Out-of-scope

- 所见即所得富文本编辑器。
- 图片裁剪、压缩、图库和图床。
- 新增任何图片专属大小或数量限制。
- RSS 自动抓取、评论和内容审核流。

### 2.3 Core User Value

发布者只需维护真正有意义的内容字段，阅读者可以先浏览摘要式列表，再进入详情阅读排版完整的正文与附件。

## 3. Scope Boundaries

### 3.1 Must Have

1. 内容模型不再暴露类型、摘要和外部链接。
2. 列表不得直接显示全文。
3. Markdown 支持标题、列表、引用、代码、表格、链接、图片等常用格式。
4. 图片上传后插入 `attachment://<id>`，渲染时通过登录鉴权解析。
5. Markdown 禁止任意 HTML 和危险链接协议。
6. 图片与普通文件共同遵守单文件默认 5 GB、每篇最多 5 个附件的现有规则，不另设图片规则。

### 3.2 Success Conditions

- 标签输入不再出现无法输入逗号的问题。
- 列表与详情有明确层级，打开详情时才标记已读。
- 正文 Markdown 与插入图片在编辑预览和已发布详情中一致。
- 旧数据中的摘要与外部链接在迁移时并入正文，不静默丢失。

### 3.3 Explicit Non-goals

- 不允许远程 Markdown 图片绕过附件鉴权。
- 不把临时 MinIO 签名 URL 持久化进正文。
- 不把 Markdown 转成服务端持久化 HTML。

## 4. Locked Decisions

### 4.1 Product Decisions

- 删除类型、摘要、外部链接。
- 保留标签，并使用胶囊输入。
- 列表筛选为全部、未读、有附件、已置顶。
- 列表显示自动提取的两到三行预览，详情显示完整 Markdown。
- 图片没有专属限制，统一使用附件规则。

### 4.2 Technical Decisions

- Markdown 源文本是唯一正文真相。
- 复用现有 `markdown-it`，关闭原始 HTML并限制链接协议。
- 正文图片只识别属于当前内容且 MIME 为图片的 `attachment://<id>`。
- 图片地址通过现有订阅附件鉴权下载接口换取可显示 URL。
- 数据迁移先把旧摘要和外链转换为 Markdown 并入正文，再删除旧列与类型枚举。

## 5. Constraints

- 本地开发只连接本机 PostgreSQL 和 MinIO。
- 不修改现有 5 GB 默认配置和最多 5 个附件规则。
- 不污染频道栏既有视觉基线。

## 6. Assumptions

- 自动预览从 Markdown 纯文本提取，最多展示约 180 个字符。
- 外部 Markdown 链接允许 `http`/`https`，以新窗口打开。
- 外部 Markdown 图片不主动加载，只允许当前内容的鉴权附件图片。

## 7. Architecture Notes

- 后端列表返回轻量预览，详情返回完整正文和附件。
- 编辑器插图时先确保草稿存在，再上传并取得附件 ID，最后插入稳定引用。
- 发布详情使用独立 Markdown 组件完成安全渲染和附件图片解析。

## 8. Risks

- 删除字段需要无损迁移已有内容。
- 图片上传成功但编辑器取消时会留在草稿附件区，由草稿生命周期和既有清理逻辑管理。
- Markdown 渲染必须防止 XSS、危险协议和跨内容附件引用。

## 9. Acceptance Criteria

- [ ] 页面不再出现类型、摘要、外部链接字段。
- [ ] 标签支持回车、空格、中英文逗号和批量粘贴。
- [ ] 列表仅显示自动预览，点击详情展示完整 Markdown。
- [ ] 编辑器可上传图片并插入正文，预览和详情均能显示。
- [ ] 原始 HTML、`javascript:` 与跨内容附件引用不能产生可执行或越权内容。
- [ ] 旧数据迁移不丢失摘要和外部链接。
- [ ] 图片没有新增专属限制。
- [ ] 前后端测试、类型检查、构建、迁移和 Playwright 通过。
- [ ] 不存在阻塞实现的核心歧义。
