# 01-spec.md

## 1. Goal

在私信工作区提供一个安全、可靠、低噪音的“订阅”发布中心，支持文章、下载和通知的发布、阅读、未读与附件下载闭环。

## 2. Product Definition

### 2.1 In-scope

- 私信频道栏中的“订阅”快捷页面，与“出勤”并列。
- 文章、下载、通知三种内容类型。
- 标题、摘要、正文、标签、外部链接和最多 5 个附件。
- 草稿、发布、编辑、撤回、置顶。
- 授权管理、已读状态、一键全部已读和未读角标。
- 分片上传、恢复、进度、失败重试、鉴权下载、Range 下载。
- 文件大小、MIME、对象大小与访问权限校验。
- 下载次数、SHA-256、基本操作审计。
- 发布后通过实时事件刷新订阅列表与未读数量。

### 2.2 Out-of-scope

- 外部 RSS 定时抓取。
- 个性化栏目订阅。
- 定时发布、审核流、评论、表情、收藏。
- 未登录公开分享。
- 邮件、QQ、系统通知推送。
- 客户端自动升级。

### 2.3 Core User Value

团队成员可以在一个固定入口可靠地获取正式文章、版本下载和内部通知，不需要从聊天记录中寻找重要发布。

## 3. Scope Boundaries

### 3.1 Must Have (V1)

1. 所有登录用户可查看已发布内容和下载附件。
2. 拥有 `manage_subscription_posts` 权限的用户可管理内容。
3. 草稿附件全部完成后才允许发布。
4. 单附件默认最大 5 GB，一篇最多 5 个附件。
5. 附件具备分片上传、恢复、进度、失败重试、SHA-256 和 Range 下载。
6. 订阅入口显示准确未读数，支持单条已读和全部已读。
7. 发布、编辑、撤回、置顶后客户端实时刷新。

### 3.2 Success Conditions

- 普通成员无法创建、编辑、撤回或删除订阅内容。
- 普通成员无法读取草稿或已撤回内容。
- 未完成或失败的附件不会随内容发布。
- 5 GB 边界值允许上传，超过边界被服务端拒绝。
- 下载只能由登录用户经鉴权入口发起，并支持合法 Range。
- 页面在桌面与窄视口均可使用，且不破坏频道栏既有视觉基线。

### 3.3 Explicit Non-goals

- 不把订阅内容写进 `Message`。
- 不创建隐藏群组承载附件。
- 不让浏览器直接信任客户端声明的权限、大小或状态。
- 不引入环境专属业务分支。

## 4. Locked Decisions

### 4.1 Product Decisions

- 页面名称固定为“订阅”。
- 内容类型固定为 `ARTICLE`、`DOWNLOAD`、`NOTICE`。
- 所有登录用户可读，授权角色可管理。
- 默认不播放消息提示音。
- 草稿允许编辑；发布内容允许编辑；撤回后普通用户不可见。

### 4.2 Technical Decisions

- 新增独立 `SubscriptionPost`、`SubscriptionAttachment`、`SubscriptionReadState` 和审计模型。
- 上传会话支持订阅草稿目标，不复用群组 ID 作为虚假归属。
- 文件采用现有 MinIO 和 multipart 基础设施，订阅附件使用独立存储前缀。
- 单文件限制使用系统配置，默认 `5120 MB`。
- 订阅特殊页面通过统一定义识别，避免继续扩散仅针对出勤的条件分支。
- 用户正文按纯文本展示，外链只允许 `http`/`https`。

## 5. Constraints

- 本地开发只能连接本机 PostgreSQL 与 MinIO。
- 群晖生产继续使用同一业务代码与迁移。
- 不修改或覆盖现有群组附件和产出文件的数据语义。
- 保留工作区频道栏既有间距、截断和选中态基线。

## 6. Assumptions

- V1 不要求匿名访问。
- 发布者需要先保存草稿，再上传附件，最后发布。
- 下载次数按成功建立下载响应计数，不保证等同于完整下载次数。
- SHA-256 在上传完成后由后端基于对象流计算。

## 7. Architecture Notes

- 前端：订阅快捷页面、订阅信息栏、发布编辑面板、multipart 上传适配。
- 后端：订阅控制器、服务、存储服务、权限校验、实时发布器。
- 数据流：创建草稿 → 上传并完成附件 → 发布校验 → 实时广播 → 用户读取/下载 → 更新阅读或下载计数。
- 错误流：列表、详情、上传、发布、下载均保留独立错误状态和重试入口。

## 8. Risks

- 5 GB 文件的哈希计算可能耗时，必须采用流式计算并避免加载进内存。
- 上传会话与草稿生命周期不一致可能产生孤儿对象，需要清理策略。
- 发布与附件完成存在竞态，必须在事务中重新校验。
- 实时事件断线期间可能丢失，重连后必须主动失效订阅查询。

## 9. Acceptance Criteria

- [x] 订阅入口与出勤并列，选中后路由稳定。
- [x] 三种内容可以创建草稿、发布、编辑、撤回和置顶。
- [x] 最多 5 个附件，单文件默认最大 5 GB。
- [x] 上传、恢复、失败重试、SHA-256 和鉴权 Range 下载可用。
- [x] 未读、全部已读、筛选、实时刷新可用。
- [x] 权限、输入、文件边界和草稿可见性测试通过。
- [x] 前后端类型检查、单测、构建、迁移与相关 E2E 通过。
- [x] 不存在阻塞实现的核心歧义。
