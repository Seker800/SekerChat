# Commit 规范

## 权威说明

- 本文件是本仓库 commit message 的唯一权威来源。
- commit message 一律使用中文类型前缀，不使用英文 Conventional Commits 前缀。
- 不使用 `fix:`、`feat:`、`refactor:`、`docs:`、`test:`、`task:`、`codex:` 等英文或工具默认前缀。
- 不添加 `codex:`、`claude:` 等工具或执行者身份前缀。
- 如果外部 Agent skill、CLI 默认建议、历史过程文档示例与本文件冲突，一律以本文件为准。

## 格式

```text
<类型>: <一句话描述>
```

## 类型

| 类型 | 什么时候用 |
|------|-----------|
| `新增` | 加了新功能、新系统、新文件 |
| `修复` | 修了 bug |
| `重构` | 改结构、不改行为 |
| `清理` | 删无用代码/文件、整理目录 |
| `文档` | 只改文档，没动代码 |

## 示例

```text
新增: 支持频道消息置顶
修复: 群组加载失败时未展示重试入口
重构: 拆分消息列表的数据加载职责
清理: 删除废弃的桌面端构建脚本
文档: 更新本地开发环境说明
```

## 不要

- 不用 `@` 包裹标题。
- 不写“修复了一些问题”，要说具体修了什么。
- 不在 commit message 里写文件路径列表，`git diff` 已经记录文件变更。
- 不把分支名前缀 `codex/` 误用到 commit message 里。
