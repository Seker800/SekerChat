# QQ 同步和个人群静音生产验收

## 发布范围

用户明确授权群晖生产上线，并将此前本地试用的指定群用于生产单向同步。Chat 前后端均更新为 v0.9.19，发布提交 `23b37038924e366676ff8e531198ac8e20e48842`，本地注解 tag 指向同一提交，未推送 Git。生产设置与账号使用生产数据库，不搬运本地测试身份、偏好或消息队列。

## 发布证据

- 现有发布脚本与本地哈希一致；部署检查 9 项通过，镜像构建成功，上传 SHA-256 一致。
- 发布前 PostgreSQL 备份完成并通过压缩、结束标志及 SHA-256 校验；五个新增迁移全部成功，累计 112 个迁移已应用。
- 前后端 healthy，真实外网入口 readiness 返回 ready，新版入口 HTML 指向本次构建的静态资源，index 使用 no-cache。
- 镜像包中平台配置摘要与群晖运行镜像一致；Docker Desktop 的索引／平台 manifest 摘要与群晖 config 摘要层级不同，不应直接比较为内容不一致。
- PostgreSQL 与 MinIO 容器 ID、启动时间未变；发布只替换应用。
- 生产 APP_IMAGE_TAG 已持久化为新版本，原环境配置受限备份保留。未修改数据库或对象存储凭据。

## 同步与通知

- 独立 rootless、只读根目录连接器通过 NapCat 现有 Docker 网络连接，私有凭据与生产 state volume 独立，自动重启策略开启。
- 最近 20 条实际历史完整导入，7 张图片无失败，20 条头像齐全。随后用户自行发出的新 QQ 消息成为第 21 个独立来源，并在生产认证 WebSocket 上观察到实时消息事件；该条传输约 5.4 秒，仅为单样本，不能代表延迟保证。
- 初次将历史导入中的计数增长误认为新消息，已当场更正；最终实时验收使用上述新来源和真实事件。维护说明不将导入计数当作实时证据。
- 生产实际消息返回的头像 content 地址返回 200、图片 MIME 与非空字节；10 个不同头像／媒体的受保护读取通过。
- 普通群和同步群个人静音切换及详情持久化通过；匿名 401、非成员 403、错误输入 400；对应实时群刷新事件通过，最终恢复不静音。
- 反向同步关闭，出站任务始终为 0。未向 QQ 发送测试消息，没有调用付费模型。
- 连接器被强制终止后自动重启恢复 healthy；修复了仅按 PID 判断存活导致容器 PID 复用时无法恢复的问题。

## 用户反馈与修复

旧浏览器标签在加载新版前保留旧页面；用户刷新后确认头像与其他界面恢复，唯一遗留是 QQ at 被转换成通用群友文字。根因是连接器转换器硬编码占位，和 Chat 部署不完整无关。

连接器改为解析群名片／昵称并保留原始 QQ 号；名称查询失败也显示 QQ 号，全体成员独立处理。查询只读，按账号和群隔离缓存，有超时、数量和容量上限，不将外部 QQ 号冒充 Chat 成员，不制造本地被 @ 提醒。12 项连接器单元测试通过。已从原始 QQ 事件严格匹配修正生产中受影响的一条测试消息；匹配来源、群、原内容和片段数量后才写入，不生成新消息或反向任务。

## 运维限制

NapCat 电脑与 Docker 需保持运行；休眠、关机及完全未捕获的离线消息不保证自动补齐。当前使用受信 LAN 入口，明确开启 LAN HTTP 选项；公网连接须使用 HTTPS。真实撤回、反向发送以及原生操作系统通知弹窗没有在本次生产验收中实际触发，不能声称已验证。

生产浏览器由用户已有正常登录会话检查，未创建生产测试账号，未保存额外浏览器凭据。
