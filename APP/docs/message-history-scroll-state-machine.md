# 消息栏历史加载滚动状态机

这份说明只定义消息栏在“向上加载旧消息”时的正确交互，不讨论实现细节。

目标体验对标 QQ / Slack / Discord：

- 用户向上浏览历史时，触发加载旧消息
- 旧消息插入到列表上方
- 用户眼前这一屏视觉上不跳
- 加载完成后不会自动连发下一页
- 只有用户继续主动上拉，才会再次触发下一页

## 北极星

一句话定义：

`加载旧消息时，当前可见内容必须保持原像素位置不动。`

不是：

- 加载后停在顶部
- 加载后回到旧消息原位置
- 加载后回到底部

而是：

- 用户在触发前看到什么
- 加载完成后仍然看到同一屏
- 只是现在继续往上滚时，能看到刚刚加载出来的更早消息

## 状态

消息栏只允许处于下面 5 个状态之一：

1. `PinnedToBottom`
   用户在底部附近，允许自动跟随最新消息。

2. `BrowsingHistory`
   用户离开底部，正在看历史。禁止自动跟随最新消息。

3. `TopEdgeArmed`
   用户已经进入顶部触发区，允许触发一次历史加载。

4. `LoadingOlder`
   已经发出“加载更早消息”请求，等待旧消息返回。

5. `TopEdgeCooldown`
   旧消息已经插入，视口已经恢复完成，但在用户重新离开顶部区之前，不允许再次触发下一页。

## 顶部触发规则

历史加载必须是“越线触发”，不是“停在顶部就一直触发”。

允许触发下一页的前提：

- 当前有 `nextCursor`
- 当前不在 `LoadingOlder`
- 当前不在 `TopEdgeCooldown`
- 用户从“顶部区外”滚进“顶部区内”

不允许触发的场景：

- 用户一直停在顶部区
- 旧消息刚加载完，但用户还没再次离开顶部区
- 图片、内容高度变化、程序写入 `scrollTop` 导致再次进入顶部区

## 视口保持规则

触发历史加载前，必须记录这两个值：

- 当前第一条可见消息的 `messageId`
- 这条消息距离消息栏容器顶部的像素偏移

旧消息插入完成后：

- 重新找到这条 `messageId`
- 计算它现在相对容器顶部的位置
- 把 `scrollTop` 调整到它回到原像素偏移

这个过程叫“可见锚点恢复”。

禁止使用这些替代方案作为最终策略：

- 只记 `scrollTop`
- 只记 `scrollHeight delta`
- 加载后强制停在 `0`
- 加载后强制停在某个固定阈值

这些做法都可能在消息高度不均匀、图片异步加载、系统消息/回复块高度变化时产生漂移。

## 滚动写入权限

在任意时刻，只允许一套逻辑拥有写 `scrollTop` 的权限。

### `PinnedToBottom`

允许写入：

- 新消息到达后的自动跟随
- 图片加载 / 内容高度变化后的自动跟随

### `BrowsingHistory`

允许写入：

- 用户真实手势滚动

禁止写入：

- 新消息到达自动跟随
- 图片加载自动到底
- `ResizeObserver` 自动到底

### `LoadingOlder`

允许写入：

- 历史加载完成后的“锚点恢复”

禁止写入：

- 自动到底
- 图片 `onLoad` 驱动的 `scrollToBottom`
- `ResizeObserver` 驱动的 `scrollToBottom`
- 本地发送消息导致的自动到底

### `TopEdgeCooldown`

允许写入：

- 用户真实手势滚动

禁止写入：

- 自动再次触发下一页

## 重新武装规则

历史加载完成并恢复视口后，不应立刻允许再次加载。

必须满足以下顺序：

1. 用户进入顶部区
2. 触发一次加载
3. 旧消息返回并恢复锚点
4. 进入 `TopEdgeCooldown`
5. 用户离开顶部区
6. 再次回到顶部区
7. 才允许下一页

这一步是防止“把所有历史一口气自动拉完”的关键。

## 验收标准

实现完成后，必须满足下面 5 条：

1. 用户在顶部附近触发历史加载后，眼前这一屏不跳。
2. 旧消息插入完成后，不会自动继续拉下一页。
3. 用户不离开顶部区时，绝不允许重复触发。
4. 用户离开顶部区后，再次回到顶部区，才允许再次加载。
5. 历史加载期间，图片加载、本地发送、新消息到达，都不能改变当前视口。
