# 群聊个人静音

## 使用

普通群顶部有“静音”按钮，点击变为“已静音”，再次点击恢复。所有群默认不静音；这是当前账号的群偏好，刷新和重新登录后保留。其他成员的提醒不受影响。群里的消息、QQ 同步及未读计数继续工作。

静音覆盖网页消息音、@ 音、重连补声及桌面提醒程序的消息提醒。取消静音后桌面提醒不补响此前静音的历史积压；已经播放或已经进入操作系统的通知不会被撤回。全局免打扰和打卡提醒是独立设置。

当前按钮面向普通群，包括 QQ 镜像群；私聊的数据结构也支持同一偏好，但本次没有扩展私聊界面。管理员旁观未加入的群没有该按钮，接口同样要求实际成员身份。

## 接口与边界

`PATCH /api/groups/:groupId/notifications` 使用普通已认证会话，正文为 `{ "notificationsMuted": true }` 或 false，只修改认证用户自己的成员记录。返回 groupId 和 notificationsMuted。匿名 401，非成员 403，非布尔值 400。

GroupResponseDto 增加可选 notificationsMuted 兼容旧客户端；服务端总是返回布尔值。数据库两条迁移分别添加默认 false 的开关与默认 0 的桌面提醒恢复截止序号。不涉及任何消息删除、AI 发言授权、QQ 路由或生产数据。

- 后端针对性 20 项通过，含个人偏好、群序列化、原有消息行为、桌面连接隔离与 HTTP 补拉推进。原有实时服务回归中 25 项通过；新增测试首轮使用不完整的消息契约样本被正确拒绝，补齐合法样本后通过，未放宽契约。
- 前端 34 项通过，覆盖普通／@ 声、补声、其他群正常提醒、取消静音恢复、API 失败不伪装成功、工作区与缓存；前后端类型、构建、lint、契约及模块边界检查通过。
- 本机真实 HTTP／PostgreSQL 验收 11 项通过：普通成员可设置、其他成员不变、默认 false、匿名及非成员拒绝、输入拒绝、列表和详情持久化、静音期间消息及未读继续、取消静音截止序号落库。
- 实际浏览器在普通测试群点击静音、刷新仍保留，再取消静音；最终恢复默认不静音。截图保留在忽略目录 `APP/.local/group-mute/ordinary-group-muted.jpg`。新增普通测试群留在本机供查看。

本次没有向真实 QQ 群发送消息、运行付费模型、修改 AstrBot 或发布生产。真实系统通知弹窗未单独实测，服务端投递和前端声音决策使用隔离测试验证。
