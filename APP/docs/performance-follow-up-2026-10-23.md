# 性能报告复核与本地修复

日期：2026-10-23。原始报告保留在 `notes/performance-review-2026-10-23.md`，本文记录独立复核、取舍和验收。

## 复核结论

| 问题 | 判断 | 本次处理 |
| --- | --- | --- |
| 生产写请求明显慢于读请求 | 真实。独立统计最近两小时：manifest 697 次，p50 3ms；heartbeat 699 次，p50 213ms、p95 991ms；read-cursor 17 次，p95 1118ms | 减少无效锁事务和可替代心跳写入 |
| 精确的 fsync 中位数 0.5 秒、RAID 磁盘是唯一根因 | 原报告测量支持落盘等待，但本次没有独立重跑该基准。生产 PostgreSQL 16.13 的 fsync/synchronous_commit 开启，wal_writer_delay=200ms，track_wal_io_timing 关闭 | 不改生产设置，不做硬件迁移，也不承诺软件修复能消除磁盘延迟 |
| 空 claim 每次都锁行 | 真实：它先锁的是始终存在的连接器行，而非空投递结果；即使只有单向绑定也会付出锁事务成本 | 先用无锁查询筛选可领取任务或过期租约，没有工作直接返回 |
| 输入每次带动历史消息重渲染 | 真实。新增测试在修复前观察到工作区 hook owner 重渲染 | 草稿使用每个 Composer 实例私有的 Zustand store，仅输入区订阅；提及候选和键盘选择也在输入区计算 |
| 历史消息全部挂载、媒体租约随历史增长 | 真实 | 超过 100 条启用 TanStack Virtual，测量动态行高，按视口挂载并释放离屏媒体；不裁掉历史数据 |
| 日期格式化器反复创建 | 真实。500 次测试循环创建 2000 个 formatter | 按 locale 和格式缓存，最多缓存 32 种组合；相同测试最多构造 3 次 |
| 读游标、presence、recovery、claim 都应关同步提交 | 不采纳统一降级。投递状态和恢复状态具有持久化约束；presence 还有审计用途；读游标已有前端合并协调器 | 只有可由后续心跳覆盖的观测数据使用事务内 `SET LOCAL synchronous_commit = off` |
| 文件缓存直接延长到一天、消息统计改缓存 | 当前收益证据不足，还涉及权限失效和统计一致性 | 保留现有语义，未做推测性修改 |

## 需要纠正的解释

- `SELECT … FOR UPDATE` 不改业务列，但会获取行锁，并可能生成 WAL，不能把这种生产基准称为严格只读。本次生产只查询设置、统计和读取日志。
- 慢写与快读的对照支持持久化路径存在瓶颈，但不等于每笔事务都独占一次同样时长的 fsync；并发事务可以共享刷盘。
- 异步提交的风险窗口取决于 WAL writer 配置与运行情况，不能把 0.6 秒说成所有部署的固定保证。没有关闭 fsync，也没有修改数据库或连接池全局设置。
- 缓存过期不等于必然重新完整下载原文件；还要看请求缓存策略、验证器和客户端私有媒体缓存。

## 实现边界

claim 的预查询同时检查连接器、双向绑定、修订号、阻塞任务和过期租约。预查询只是提示；有工作后仍进入原来的锁事务重新检查。并发领取、租约恢复、started/uncertain 的防重发约束均保留同步提交。新任务恰好在预查询后入库时，下一次轮询会发现它。

相同心跳观测在 15 秒内不重复写入；连接状态或群目录变化立即保存。目录比较不受 JSON 对象键顺序影响。连接器在独立程序中，当前仓库没有其轮询循环，因此没有声称改变客户端 HTTP 轮询间隔；本次直接消除了空轮询锁事务，并降低服务端心跳写入频率。

虚拟列表复用现有阅读模式与翻页协调器，通过窄的导航适配器捕获和恢复消息位置。日期分隔线与消息分别测量；恢复时由库跟踪动态行高。滚动后等视口提交再捕获可见锚点，避免把尚未挂载的新视口误认为没有锚点。短列表保留原 DOM 排列，引用跳转可以定位已加载但未挂载的消息。单条消息使用 React memo。

## 验证证据

- 修复前失败、修复后通过：空 claim 不开事务、相同心跳不重复写、formatter 构造次数、输入不触发工作区 hook owner 重渲染、1000 条历史仅挂载有限消息。
- 本机真实 PostgreSQL 集成验收通过：空闲、旧修订号积压和结果不明阻塞均只读；并发 claim 只成功一次；过期 claimed 可重新领取，过期 started 变 uncertain；心跳更新和 JSON 键顺序去重正确，后续事务仍为同步提交。集成测试显式检查 DATABASE_URL 是 loopback，并在结束后删除自己的测试数据。
- 前端全量单测：61 个文件、352 项通过。
- 后端全量单测：493 项通过，5 项跳过；额外显式启用的本地数据库验收及 4 项性能单测通过。
- 13 项相关 Playwright 验收通过：1000 条历史、离屏引用跳转、90→120 条切换虚拟化、160→190 条历史 prepend、原有短历史锚点、输入／回复、上传及图片预览。已查看长历史与图片场景截图。
- 前后端类型检查、前端生产构建、bundle 预算、相关文件 ESLint 和架构检查通过；架构检查为 0 循环、0 边界违规。
- 扩展工作区 smoke 共 31 项，其中 30 项通过；“打包时添加到产出”旧截图仍期待图片，而当前 fixture 显示缩略图不可用。另取当前 HEAD 的干净源代码在临时目录、独立端口复跑，得到相同的图片占位差异，确认是既有基线问题；没有更新快照掩盖差异。

没有部署、push 或修改生产数据。没有把原有文档／skills 改动和未跟踪的原始报告纳入本次提交。生产端实际收益需要在另行授权发布后按同窗口请求日志复测；未做四小时内存稳定性或真实 NAS 故障恢复测试。
