# QQ 群同步：维护与本地验收

## 当前状态

已实现并于 2026-10-18 随 v0.9.19 发布到群晖生产；详见[生产验收](qq-bridge-production-2026-10-18.md)。此前2026-10-18 用户已授权指定真实 QQ 群到本地的单向试用，最近 20 条与后续自然新消息已进入本机。运行拓扑与选择见 [ADR 0006](adr/0006-qq-bridge-extension.md)。

Chat 管理页面的“扩展”入口提供连接器创建、凭据撤销、群绑定、单向／双向、暂停和积压处理。连接器与群绑定默认关闭。凭据仅返回一次，服务端保存 SHA-256 校验值。管理接口复用既有浏览器会话与系统配置权限；连接器走独立 Bearer 认证，不借用管理员会话。

## 接口与持久化

- 管理：`/api/extensions/qq-bridge` 及其 connectors、bindings、deliveries 子资源。响应 DTO 发布到现有 OpenAPI 与 contracts，前端直接引用生成类型。
- 明确授权的历史导入：`POST /api/extensions/qq-bridge/bindings/:id/history`，单条 `IngestQqMessageDto`。需要普通管理会话及目标群管理权限，检查路径绑定、启用状态和修订号；连接器令牌不能调用。唯一来源键去重，保留原始 QQ 时间；不改变普通入站的启用时间门槛。当前没有自动历史追赶或前端批量导入按钮。
- 连接器：`/api/integrations/qq-bridge` 的 manifest、heartbeat、messages、recalls、media、deliveries 领取／开始／确认与图片读取。
- 消息：保留内部 senderId，外部作者快照写入 externalAuthor，对外增加可选 source、externalAuthorId、sourceOccurredAt。HTTP 历史、引用与实时推送使用相同序列化。
- 媒体：复用 FileObject 和 MinIO，外部头像有正式外键引用和群阅读权限。QQ 用户不成为群成员，不生成假的在线和未读人数。集成审计主体具有 integrationKind 标记；会话签发、刷新与校验均拒绝该身份，即使误清停用标记也不能登录。
- 出站：MessageDeliveryIntents 在原消息事务内登记任务，QQ 扩展注册一个窄的写入处理器。QQ HTTP／WebSocket 网络调用不在消息事务或 outbox 实时推送中执行。
- 群路由：三次新增迁移均未涉及旧业务数据删除；第三次只增加集成身份标记。第二次迁移中的自定义部分唯一索引保障未归档绑定一对一；Prisma 使用普通索引描述，应用查询需显式过滤 archivedAt。

## 启停与异常操作

1. 创建连接器凭据，配置连接器程序；在管理页确认其连接状态。
2. 创建 QQ 账号／群与 Chat 群绑定。核对 Chat 群的可见范围后，再明确启用，只接收新消息。
3. 双向同步需单独开启，默认不回传内部机器人消息。Chat 回传采用发言人姓名前缀。
4. 关闭连接器或绑定会禁止新同步和新发送领取。已发出的网络请求可能完成，其结果仍应如实记录。
5. 重新开启时，未发送的旧任务默认继续暂停；可显式继续或放弃。原先处于 started 的过期任务转 uncertain，不能用“继续旧任务”重发它。
6. uncertain 需要先到 QQ 核对，再填写确实发送的消息标识，或明确放弃。已发送消息编辑后，QQ 原文不变，管理页提示不同步。
7. 解除绑定需先暂停，并处理 uncertain／started。解除保留旧消息和来源记录，可新建另一绑定；旧 UUID／修订号不能写入新绑定。

## 本地验证方法

使用本机 PostgreSQL／MinIO，严格按 [本地运行说明](local-dev-runbook.md) 启动后端。跨仓库连接器位于同级 SekerMaiBot 的 `qq_bridge/`，该目录 README 给出运行与集成测试命令。

集成脚本会拒绝非本机回环的 API、数据库和 MinIO 地址，只连接自身创建的模拟 OneBot WebSocket。测试凭据只保存在进程内；结束时先停用／撤销，再清理本次创建的独立测试账号、群和对象；可显式保留测试资料供排查。测试产生的对象位于独立测试群命名空间，不修改既有用户群内容。

已验证：100 个源事件各重放三次仅生成 100 条外部消息；昵称与群名片、不同作者、头像／图片本地保存及权限；图文片段、引用、双方撤回；双向消息、QQ 自身回声去重、模拟 AstrBot 自身发言；反向图片与引用；发送超时不重发；普通 Chat 写入不等 QQ；暂停、陈旧修订号、重新绑定与凭据撤销。

首轮联调中的两个判断已修正：建群自带系统消息，因此去重按 externalKey／来源统计；Nest 对无任务返回成功空正文，连接器必须把它解释为无任务，不能把 JSON 解析失败变成整个入站循环中断。后者已添加独立回归测试，并在完整本地链路复验。

自动化结果和桌面／手机可见截图放在 Git 忽略的 `APP/.local/qq-bridge/`。核心历史、实时发布和原有业务回归使用既有 backend tests、契约、类型及架构边界检查；具体最终结果以该目录的结果文件和本次交付记录为准。

## 尚未由本地模拟证明的内容

真实 QQ 的自身消息上报配置、头像／图片 CDN 的实际可达性、QQ 撤回权限、离线历史补取以及真实群中的发送频率观感。不得把模拟 OneBot 成功当成这些平台能力已经现场通过。生产发布和真实群测试均需用户当前任务明确授权。

## 真实群本机试用补充

最近 20 条包含 7 张图片、2 位作者，均有头像；后续至少 2 条自然新消息到达。头像、GIF、昵称和来源标识在实际页面可见。历史消息展示使用 `sourceOccurredAt`，日期分隔和紧凑分组使用相同时间；消息排序和事件游标不改。

本机代理 fake IP 曾使媒体请求被地址保护拒绝。连接器增加显式 HTTPS DNS 配置，仍拒绝非 QQ 域名、私网地址及重定向。失败的首次本地预览已归档，活动频道使用修复后重新导入的数据，没有修改来源时间。

历史管理入口真实 HTTP 验证覆盖匿名／连接器拒绝、普通成员拒绝、绑定不一致、修订失效、重复去重与实时旧消息过滤；本轮新增后端 3 项历史单元、前端 1 项时间显示回归，连接器新增转换与 DNS 检查，共 8 项连接器测试通过。后端、前端构建与契约检查通过。

开发时观察到一次读游标 404 后的频道列表类型错误；刷新恢复，随后自然新消息没有再次触发。根因未证实，不声称已修复该潜在既有问题，后续复现需保存网络响应与缓存证据。截图保存在忽略目录，不保存真实聊天到版本文档。以上为本地阶段记录。生产单向同步已另行验收；反向真实发送、真实撤回与持续离线补齐仍未验收。
