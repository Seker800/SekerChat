# 辅助数据保留策略

定时清理只处理已经失效或终结的记录。任务按小批量执行，失败后下次重试，不触及仍在运行的上传、待投递事件或业务对象。

| 数据 | 保留与处理 |
| --- | --- |
| 浏览器上传续传索引 | 按服务端会话创建时间保留 24 小时，读取时淘汰过期或无效项，最多保存 100 项。普通上传失败保留有效索引供续传；取消或成功时删除。 |
| `UploadSession` | 超过 24 小时仍为 `INITIATED` 的 multipart 上传先中止，再标记为 `ABORTED`。`COMPLETED` / `ABORTED` 超过 30 天且没有待处理对象清理或未结束的终结任务时删除会话记录。 |
| `FAILED` 上传 | 终结重试耗尽且超过 7 天后，确认没有数据库业务对象引用；若对象已组装则删除对象，否则中止 multipart 上传。清理成功才转为 `ABORTED`。 |
| `RefreshToken` | 到期超过 7 天或撤销超过 30 天后删除。 |
| `OutboxEvent` | 已投递事件超过 30 天删除。失败事件保留 180 天供排障与人工处理，之后在同一事务中归档至 `OutboxDeadLetter` 再删除原记录。归档保留事件载荷、重试次数和最后错误；归档失败时原事件保留。归档记录再保留 365 天。 |
| `PresenceLog` | 超过 400 天的完整用户工作日先按当前考勤时区计算并保存 `PresenceDailySummary`，再在同一事务中删除该日原始事件。日摘要保留在线时长、首末在线时间及日终在线／免打扰状态，用于历史报表与后续日期的跨日衔接。 |

`PresenceDailySummary` 是历史快照：如果之后调整考勤时区，已压缩日期不会按新时区重算。需要改变历史口径时，应从备份恢复原始事件并按新配置重新生成摘要。处理失败事件时先检查归档记录及业务端是否已经生效，再决定是否人工重投；需要超过归档保留期的记录时，应提前导出。

建议在对象存储上额外配置 `AbortIncompleteMultipartUpload` 生命周期规则作为应用定时任务失效时的兜底。生产规则的配置和启用属于独立的生产变更。
