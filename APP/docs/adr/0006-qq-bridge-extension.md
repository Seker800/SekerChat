# ADR 0006: QQ 同步采用内置扩展与独立 NapCat 连接器

- 状态：接受；本地验证后，用户于当前任务明确授权生产发布。v0.9.19 已在群晖发布，独立连接器在 NapCat 主机常驻，仅开启 QQ → Chat；最近 20 条和用户新发消息均通过生产验收。
- 日期：2026-10-18。

## 选择与理由

Chat 保持模块化单体，新增随主程序构建的可开关 QQ 扩展。独立连接器直接订阅 NapCat OneBot 事件，通过范围受限的集成凭据访问 Chat API。AstrBot 继续独立处理 AI 对话，其白名单、事件中止、回复策略与运行状态均不作为同步前置条件。

核心提供外部消息作者快照、图片暂存和消息写入能力；QQ 扩展负责群绑定、QQ 消息映射、凭据与投递租约。普通 Chat 消息的现有发送者字段保留，新增展示身份字段为可选。QQ 群友不创建内部 User 或 GroupMember。仅有一个带 integrationKind 标记的停用集成账号承担写入审计责任。会话签发、刷新、HTTP 与实时认证统一拒绝集成身份，即使停用标记被错误清除也不能登录；既有 Bot 管理还会按 CLI_BOT 角色筛选，不把该主体作为 AI 机器人。

核心通过窄的 MessageDeliveryIntents 注册接口，在消息事务内写入 QQ 投递意图。调用 QQ 的网络动作完全在连接器执行，QQ 故障不改变 Chat 消息已成功提交的事实。网络动作开始前持久化 started；响应不明转 uncertain，人工核对后再处理，禁止盲目重发。

## 考虑过的方案

- 从 AstrBot 插件／日志取消息：能复用现有连接，但同步会受 AI 白名单、事件中止和重启影响，归档也没有媒体内容。
- 为每个 QQ 用户创建影子账号：初期展示改动较少，但会混入内部认证、权限、群成员与回执，长期边界不清。
- 先建设第三方插件热加载平台：当前没有独立分发和第三方代码运行的实际要求，会增加版本、迁移、权限和沙箱成本。
- 每条消息提交后临时发送 QQ：进程中断可能丢任务，响应丢失可能重复发言，不能接受。

## 代价与边界

增加独立连接器进程和私有持久化队列。Chat 端只在有系统配置管理权限时允许配置连接器和群绑定；首发不开放普通群管理员自助创建凭据。更细的扩展管理授权需要明确新需求。

QQ 到 Chat 可显示每位群友的昵称和头像；Chat 到 QQ 由桥接账号发出，正文注明发言人。源消息可以拆为多个原生消息片段。真实精确 @、编辑已发送 QQ 消息、历史媒体迁移和其他 QQ 消息类型不在本版本支持范围。

群绑定解除后只归档绑定，保留来源映射，使用自定义部分唯一索引保证每个 QQ 群和 Chat 群仅有一个未归档绑定。旧队列绑定旧 UUID 和修订号，不会自动换投新群。发送结果不明时先处理任务再解除。

图片先保留可恢复的 FileObject 暂存引用，再写 MinIO；消息正式引用后受外键保护。清理先锁记录再检查外部头像、消息和分享引用，与上传预留互斥；近期外部图片保留至少一天宽限期，后台串行处理此类对象以限制数据库连接占用。数据库与对象存储没有跨系统事务的保证。

## 验证与重新评估

本地模拟 NapCat，真实使用本机 API、PostgreSQL 和 MinIO；用重复投递、自身回声、丢发送响应、重启、撤销凭据、暂停和重新绑定检查边界。详见 [维护与验收说明](../qq-bridge.md)。真实 QQ 自身消息上报、CDN 访问与离线补取仍需另行授权现场验证。

出现第二个实际外部平台、第三方分发需求或实测资源隔离问题后，再评估提取共享扩展平台。不得因为新增一个功能就把 Chat 拆成多个业务服务。

历史导入是显式管理动作，独立入口验证配置与群管理权限；实时连接器不能申请跳过启用时间。历史仍复用来源去重、图片、引用与消息写入能力，展示原始时间，不改内部事件游标与入库排序。只对用户指定的近期样本做有界导入，不增加自动无限补录。
