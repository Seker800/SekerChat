# ADR 0007: 群静音属于个人会话偏好

- 日期：2026-10-18。
- 状态：已在本机实现与验证，生产未发布。

## 选择

所有普通群均提供个人静音开关，默认不静音。偏好归属于当前账号的 GroupMember，不属于 QQ 桥接绑定或整个群。普通成员可以设置自己的偏好，管理员也不能借此接口修改他人。保留消息接收、群内协作、未读和阅读游标，单独控制提醒。

数据库新增 notificationsMuted（默认 false）及 notificationsMutedThroughEventSequence（默认 0）。取消静音时，在成员行锁事务内记录该群当前消息序号，桌面提醒从这之后恢复，避免 WS 被静音过滤但客户端旧游标随后补响积压。重复的取消静音不推进截止序号。

HTTP 群列表、详情、工作区 bootstrap 返回当前用户的 notificationsMuted，不在成员列表中公开他人的偏好。设置变更复用既有 group.updated 刷新，不增加新的 QQ 协议或配置；广播不携带静音值。实时刷新失败不推翻已经提交的偏好，重新读取可以恢复。

网页在现有 useNotification 里统一检查该群偏好，覆盖普通声、@ 声及重连补声；通知使用全部已加载会话而非仅当前工作区。桌面程序的服务端 WS 投递单独过滤提醒连接，浏览器仍接收原事件；提醒 HTTP 补拉读取同一偏好和截止序号，过滤提醒同时推进扫描游标，浏览器历史接口不变。

## 考虑过的方案

- 只给 QQ 扩展加开关：用户明确要求所有群适用，且通知与消息来源无关。
- 仅在 localStorage 保存：不能表达账号的跨设备偏好，也不能控制独立桌面提醒。
- 静音时停止 WebSocket 订阅或同步：会阻断消息与未读，与静音语义不符。
- 仅过滤桌面 WS：重连后的 HTTP 补拉仍会出声；仅按当前布尔值补拉则可能在取消静音后补响旧积压。

## 代价与重新评估

新增两次兼容迁移，均只在本机应用；有在线提醒连接时，每个消息事件额外读取一次该群当前提醒偏好，不能依赖成员缓存的 30 秒 TTL。当前服务端依旧单实例，未引入独立通知服务。网页全局免打扰、打卡提醒和已有系统通知策略继续由各自规则控制。

验证涵盖普通群默认、个人隔离、权限、输入校验、持久化、失败提示、普通／@／补提醒、桌面 WS 与 HTTP 游标、取消静音边界、实际浏览器点击和刷新。尚未在真实系统通知弹窗上做录屏验收；没有发真实 QQ 测试消息或发布生产。
